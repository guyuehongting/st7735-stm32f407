# 05 · 测屏程序 MODE 1~9

> `test/main.c` 是找引脚时用的程序，保留了 9 个模式。
> 它不是为了日常使用，而是为了**在什么都不知道的情况下把引脚挖出来**。

---

## 怎么切换模式

文件第 40 行附近：

```c
/* MODE = 1 : 全量扫 SDA x CS x DC（169 组，56 秒）
   MODE = 2 : 手动确认
   MODE = 3 : 定点测试（CS 只试 PC14/PC15）
   MODE = 4 : 8 组关键组合 x 8 种颜色
   MODE = 5 : 每组先 Clear_Panel 再测
   MODE = 6 : 九步诊断
   MODE = 7 : INVON 反显扫描（24 组）
   MODE = 8 : 两套 CS/DC 顺序各填 4 色
   MODE = 9 : 全新接线 SPI1 最小点亮      */
#define MODE            8
```

改完重新编译烧录。**不要用 `#if` 切换** —— 会导致"函数定义未引用"的警告，
用 `if / else if` 分发即可。

---

## MODE 1：全量扫

```
SDA  : PC3 / PB15（由 SDA_MASK 控制）
CS   : 13 个候选
DC   : 13 个候选
合计 : 169 组（每个 SDA），约 56 秒
```

**判据**：屏幕变绿。

**这是最原始的一版，判据依赖 6 个环节，实际很难中。** 建议直接用 MODE 8。

---

## MODE 2：手动确认

把已经找到的 CS/DC 填进文件顶部的宏，只测这一组：

```c
#define F_CS_NAME       "PC15"
#define F_CS_PORT       GPIOC
#define F_CS_PIN        GPIO_PIN_15
```

用来快速验证"是不是这一组"，不用等完整扫描。

---

## MODE 3：定点测试

CS 只试 PC14 / PC15（已经收窄到两个），DC 试其余 12 个。

```
2 × 12 = 24 组，约 45 秒
```

**前提**：已经确认 CS 在 PC14/PC15 里。

---

## MODE 4：8 组关键组合 × 8 色

只测最可疑的 8 组，每组不同颜色。

**这是第一次抓到花屏的模式** —— `#007` 洋红、`#008` 橙。

**局限**：屏幕一旦变花就改不动了，后面的组全部无效。

---

## MODE 5：每组先清屏

在 MODE 4 基础上，每组开始前 `Clear_Panel()` 硬复位回白屏。

**这是第一个"判据干净"的模式。** 实测 `#9` / `#21` 花屏，其余全白。

---

## MODE 6：九步诊断

固定 `CS=PC15 / DC=PC14`（本项目的最终答案），把过程拆成 9 步，一步停 2.5 秒：

| 步 | 动作 | 期望 | 实际能看出什么 |
|---|---|---|---|
| 1 | `Clear_Panel` | 纯白 | 硬复位是否有效 |
| 2 | 初始化 + DISPON，**不填色** | 纯白 | 初始化有没有副作用（花 = GRAM 随机值，正常） |
| 3 | **INVON `0x21`** | 变黑/反色 | **命令通路通不通** |
| 4 | INVOFF `0x20` | 变回白 | 命令能否重复生效 |
| 5 | 填红 | 纯红 | 像素通路通不通 |
| 6 | 填绿 | 纯绿 | |
| 7 | 填蓝 | 纯蓝 | |
| 8 | 填黑 | 纯黑 | |
| 9 | 填白 | 纯白 | |

**这是最有信息量的模式。** 跑一轮就能回答三个问题：

1. 命令通不通（STEP 3）
2. 参数通不通（STEP 2 有没有异常）
3. 像素通不通（STEP 5~9）

实测输出：

```
001：STEP 2 之后都是花的
     STEP 3 花的闪了一下，STEP 4 再闪了一下，后面就不变了
002：STEP 1 白色就是白色，STEP 2 花
     STEP 3 闪了一下，后面不变，一直花
```

→ 命令通、数据断 → CS/DC 接反。

---

## MODE 7：INVON 反显扫描

用 `0x21` 当探针，扫 24 组：

```
CS = PC14        DC = 12 个脚
CS = PC15        DC = 12 个脚
```

每组流程：

```
Clear_Panel  → 硬复位回白屏
Pins_HighExcept → 除 SDA 外全拉高
CS 拉低
完整初始化
0x21 INVON
停 1.5 秒 ← 就看这 1.5 秒
0x20 INVOFF
```

**判据**：屏幕变黑（或任何变化）。

**局限（重要）**：`0x21` 无参数，所以两种 CS/DC 顺序都能让它生效，
**这个模式区分不了顺序**。它只能回答"命令通路通不通"。

实测：只有 `#009` / `#021` 有变化，其余 22 组全白。

---

## MODE 8：两套顺序各填一遍色（最终定案用的）

```
PHASE A   CS=PC15  DC=PC14   -> 红 绿 蓝 白（各 2 秒）
PHASE B   CS=PC14  DC=PC15   -> 红 绿 蓝 白（各 2 秒）
```

**判据**：哪一半出纯色。

这是**最省时间、最不需要推理**的模式。一次烧录 16 秒，直接看结果。

本项目实测：**PHASE A 通过**。

---

## MODE 9：全新接线 SPI1 最小点亮

如果你决定拆下来重接，用这套更干净的引脚：

```
VCC  -> 3.3V
GND  -> GND
SCL  -> PB3    (SPI1_SCK,  AF5)
SDA  -> PB5    (SPI1_MOSI, AF5)
RES  -> PB10   (硬件复位)
DC   -> PB1
CS   -> PB0
BLK  -> 3.3V
```

**为什么换这套**：

- PC14/PC15 在**备份域**，只能 3mA、跑不快
- PB0/PB1/PB3/PB5/PB10 都是普通 IO，驱动能力强
- SPI1 挂 APB2（84MHz），`/128 = 656kHz` 余量充足

MODE 9 只做最小必要动作：

```
硬件复位(RES 低 30ms -> 高 150ms)
SWRESET -> SLPOUT -> COLMOD -> MADCTL -> DISPON
CASET/RASET 全显存 -> RAMWR -> 填色
红 绿 蓝 白 黑 循环，每色 2 秒
```

不掺 gamma、不掺 INVON、不碰 PC14/PC15。

## 各模式的时间成本

| MODE | 组数 | 耗时 | 判据可靠性 |
|---|---|---|---|
| 1 | 169 × SDA | 56 秒 ~ 1 分 50 | 低（依赖 6 环节） |
| 3 | 24 | 45 秒 | 低 |
| 4 | 8 | 20 秒 | 低 + 会"粘" |
| 5 | 24 | 60 秒 | 中（清屏后干净） |
| 6 | 9 × 2 | 45 秒 | **高（分层探针）** |
| 7 | 24 | 90 秒 | 中（只能测命令通路） |
| 8 | 8 | 16 秒 | **高（直接给答案）** |
| 9 | 5 循环 | 一直循环 | 高（新接线专用） |

**如果重来一次，我会直接用 MODE 6 + MODE 8，一共 1 分钟搞定。**

## 编译注意

- `扫描引脚.c` 是空壳（只有注释 + typedef），**不产生任何符号**。
  它留在工程里是为了避免"从 Keil 里 Remove File"时误点 Delete。
- 如果编译报 `L6200E: Symbol main multiply defined`，
  说明工程里有两个 `main`，检查是不是还有别的 `.c` 定义了 `main`。
- ARMCC 5 默认 C90：**变量必须在函数开头声明**，`for (uint8_t i = 0; ...)` 会报错。
