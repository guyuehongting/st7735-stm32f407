# 04 · 方法论：怎么设计一个能用的定位判据

> 这次最大的教训不是"哪个引脚"，而是**判据本身要先对**。
> 判据错了，扫一千组也没用。

---

## 一、白屏 vs 花屏：最便宜的一个判据

ST7735 是**常白（normally white）** TN 屏：液晶不加电时是透光的，所以未初始化就是白的。

| 现象 | 物理含义 | 能排除什么 |
|---|---|---|
| **纯白** | 面板一个字节都没收到 | 供电、背光可能没问题，但 SPI 链路至少断一处 |
| **花屏** | 面板收到了字节，但命令/数据分界错了 | **供电、背光、驱动 IC、SPI 时钟、数据线全部是好的** |

能出花屏，就把问题范围从"硬件 + 全部接线"缩到"**只有 DC 这一根**"。

这个判据比"闪一下红"灵敏得多，而且不依赖人的反应速度。

---

## 二、探针要选"依赖最少"的那个

不同的判据，依赖的环节数量完全不同：

| 判据 | 依赖什么 | 环数 |
|---|---|---|
| 屏幕变绿 | 命令对 + 参数对 + COLMOD 对 + 窗口对 + MADCTL 对 + 偏移对 | **6** |
| 屏幕变黑（`0x21` INVON） | 只要命令能到面板 | **1** |

`0x21` 反显是整屏动作：

- 不经过显存（不需要窗口）
- 不看 COLMOD
- 不看 MADCTL
- 不看行列偏移

所以它是 ST7735 上**最干净的探针**，专门用来回答一个问题：

> **命令到底有没有进到面板里？**

### 但探针也有盲区

`0x21` 无参数，所以：

```
CS=PC14 / DC=PC15  →  能进（命令期 CS 恰好低）
CS=PC15 / DC=PC14  →  能进（CS 一直低）
```

**两种接法都会"闪"，所以它区分不了 CS/DC 顺序。**

要区分顺序，必须换成依赖 DC=高 的动作：

- 带参数的命令（`0x2A` 窗口、`0x36` 方向）
- 写像素（`0x2C` + 数据）

### 结论：探针要分层用

```
第 1 层  0x21 INVON        → 命令通路通不通？（1 个依赖）
第 2 层  0x36 改方向       → 参数通路通不通？（2 个依赖）
第 3 层  0x2C 写纯色       → 像素通路通不通？（3 个依赖）
```

**一次只增加一个依赖**，故障点就自动暴露了。

## 三、盲测必须保证每组初始状态可复位

### "花屏是粘的"

一旦面板被点亮并显示乱码，**后面所有错误组合都改不动它**。
后续每一组看起来都是花屏，无法区分哪一组真的生效。

这次因为这个，整轮 24 组数据全部作废。

### 解法：每组开始前硬复位

RES 一定在候选引脚里，所以把所有候选脚一起拉低就行：

```c
/* 全部拉低 150ms：RES 被拉低 → 面板复位 → 白屏 */
for (i = 0; i < POOL_N; i++) { ...GPIO_PIN_RESET; }
HAL_Delay(150);

/* 全部拉高：出复位，面板处于"已上电未初始化"的干净状态 */
for (i = 0; i < POOL_N; i++) { ...GPIO_PIN_SET; }
HAL_Delay(150);
```

注意：**SDA 那根脚要跳过**，它是 SPI 复用，不能当 GPIO 拉。

### 一个副作用

全拉低的时候，如果某个脚是 BLK（背光），屏幕会闪一下暗。
这反而是个额外的信息 —— 但不要指望它可靠，这次实测 10 个脚全拉低屏幕一点没变暗。

## 四、多组合盲测：给每组不同颜色

不要"都是绿色"。理由：

- 绿色会留在屏幕上，后面的组改不动它，你无法判断是哪一组留下的
- 用户的眼睛跟不上 0.9 秒一次的刷新
- 不同颜色可以事后对上号，不依赖实时反应

```c
uint16_t cols[8] = { C_WHITE, C_YELLOW, C_CYAN, C_GREEN,
                     C_MAGENTA, C_RED, C_BLUE, C_BLACK };
```

更好的做法：**让串口打印编号，屏幕上只出现一种颜色**，
看到颜色后回头查串口日志里的编号。

## 五、不要用别的板子的引脚分配去裁剪候选集合

第一轮我把用户列的 12 个脚砍成 4 个，理由："PE2~PE5 是按键，不可能接屏"。

**结果：48 组全白，白扫一轮。**

用户自定义的板子，引脚分配只能实测，不能假设。
用户列出来的每一个脚都要扫，宁可多花 60 秒。

## 六、给用户写测试程序的三条硬规则

### 1. 早期绝不能 `Error_Handler()` 死循环

```c
/* 错误示范 */
if (HAL_UART_Init(&huart1) != HAL_OK) { Error_Handler(); }   /* 静默卡死 */
```

一旦卡在这里，串口不打印、背光不亮、LED 不闪，用户只能看到"什么都没发生"。

正确做法：

```c
/* 串口改纯寄存器，不依赖 HAL 模块开关 */
USART1_InitRaw(16000000u, 115200u);
U_Send("[1] BOOT OK\r\n");       /* 第一句在 HSI 就发出去 */
```

### 2. 必须有明确的进度信号

- LED 灯语（3 快闪 = 进 main，5 快闪 = 时钟 OK，2 慢闪 = 时钟失败）
- 串口分步打印 `[1] [2] [3]`
- 结尾打印"扫描结束"横幅

用户抱怨过"跑完不知道什么时候结束"，这个必须解决。

### 3. 打印复位原因

```c
U_Send("RCC_CSR = 0x");
U_Hex32(RCC->CSR);
RCC->CSR |= RCC_CSR_RMVF;       /* 清标志 */
```

`BOR` 出现 = 供电不足，可以直接排除一大类问题。
这次实测是 `PIN`，所以电源方向从一开始就不用查。

## 七、时间成本对比

| 做法 | 耗时 | 结果 |
|---|---|---|
| 扫 169 组（判据是坏的） | 56 秒 × 多轮 | 全部白扫 |
| 扫 24 组（判据是坏的） | 90 秒 × 2 轮 | 全部白扫 |
| **九步诊断（判据正确）** | **22 秒** | **直接定位到"命令通、数据断"** |
| **两套顺序各填 4 色** | **16 秒** | **直接定案** |

**判据对了，8 组就够了。**

---

## 八、一句话总结

> 遇到"扫描永远只有两种结果"的情况，
> **先停下来审一遍判据代码**，而不是继续扩大扫描范围。
>
> 因为判据错的时候，扫描范围越大，浪费的时间越多。
